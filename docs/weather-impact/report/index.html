Effect of using oracle weather instead of historical forecasts

Both comparisons use the same 8 walk-forward CV folds and the same model settings. The oracle comparison uses the Open-Meteo Historical Forecast files as weather features; the forecast comparison uses the safe-lead historical forecasts (day1 for 1h/12h, day2 for 24h). Positive deltas mean the forecast-weather run is worse, i.e. the oracle score was optimistic.

KumoForecast only accepts past covariates. Its run uses oracle/analysis past weather in both comparisons, so it is shown in the table but excluded from the weather-impact charts. Its near-zero delta is expected.

Fold-level oracle vs forecast by horizon

Each panel is one horizon. Markers show the mean paired difference (oracle − forecast); negative means the oracle-weather error is lower. Large markers: pooled mean difference over all test rows, with a 95% moving-block bootstrap interval (14-day blocks over daily differences; conditional on the fitted models, it ignores training randomness). Small dots: mean difference in each of the 8 CV folds (one dot per fold; hover shows the fold). Folds are not independent, so no t-interval across folds is shown. MAPE uses the median prediction; pinball loss is averaged over the 5%, 50% and 95% quantiles for that horizon. KumoForecast is excluded from these panels (see the note above).

Interpretation

  • Oracle weather makes the scores optimistic, mostly at 12h and 24h; 1h is nearly unchanged because recent load dominates.
  • The degradation differs by model. Kumo-Tabular degrades most in absolute terms, while Chronos-2 and TabICL degrade less.
  • The top model remains Kumo-Tabular, but its margin over the others shrinks under forecast weather.
  • These forecast-weather results are still conservative compared with using the latest model run (our forecasts have fixed 24h/48h leads).
